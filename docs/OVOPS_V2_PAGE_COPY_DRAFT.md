## 首页

**H1：** 把 AI 和数字化系统落地到真实业务流程。  
**副标题：** 原点向量是企业 AI 应用与数字化系统落地服务商，围绕官网与门户、业务系统、知识库、自动化、营销内容和实施咨询，帮助团队从一个明确的问题开始建设可用、可维护的能力。  
**主 CTA：** 讨论一个业务场景（仅连接至已确认联系路径）  
**次 CTA：** 查看服务方式

### 你可能正在面对的情况

- 官网陈旧、询盘路径不清，客户看不懂你能解决什么问题。
- 内部流程依赖 Excel、微信与人工转发，状态无法追踪。
- 产品资料、制度、话术和 FAQ 存在网盘，却找不到、用不起来。
- 销售与客服重复回答，口径和证据不一致。
- 库存、订单、生产或项目数据分散，管理者看不到全貌。
- 内容、官网、社媒和 AI 搜索可见性彼此脱节。
- 多个工具之间重复录入，流程无法自动化或复盘。
- 团队试过 AI，却没有一个稳定进入日常业务的场景。

### 从一个可界定的问题开始

我们不把“上 AI”当作目的。先共同界定业务目标、现有资料、协作角色和可验证的试点范围，再决定是否进入下一阶段。

## 解决方案页：六大可采购服务

**H1：** 从诊断到试点，把 AI 项目做成可交付的工作流。  
**导语：** 每项服务都应写清适合谁、需要什么输入、交付什么、暂不包含什么，以及如何确认下一步。周期、报价和结果承诺均以双方确认的范围为准。

| 服务 | 文案方向 |
| --- | --- |
| 企业网站与数字化门户 | 为需要获客、展示、招商或客户入口的组织，建设官网、多语内容与数字化门户；典型交付物为信息架构、页面、内容与 SEO/GEO 方案。周期待确认/范围评估。 |
| 企业业务系统定制 | 为仍靠表格、重复录入和人工协调的团队，梳理流程并建设内部系统、权限与数据看板。周期待确认/范围评估。 |
| AI 知识库与智能助手 | 为资料复杂、客服销售口径不一的团队，整理知识、证据、问答与转人工边界，先验证可控助手。周期待确认/范围评估。 |
| AI 工作流与自动化 | 为重复性运营、内容或协作任务，设计可复盘的自动化与岗位助手。周期待确认/范围评估。 |
| AI 营销与内容运营 | 为需要连接官网、FAQ、社媒、内容与 AI 搜索可见性的品牌，建设问题库、内容矩阵与运营复盘。周期待确认/范围评估。 |
| AI 诊断与实施咨询 | 为不确定从何开始的管理团队，完成业务诊断、优先级、实施范围与验收标准。周期待确认/范围评估。 |

每项均提供“了解方案”与“讨论需求”路径；价格仅在成熟、经负责人确认的报价体系存在后展示。

## 行业/场景页

**H1 模板：** 面向[行业/团队]的 AI 与数字化系统：先解决[具体问题]。  
结构：典型问题 → 适配服务 → 输入资料 → 交付边界 → 常见问题 → 联系 CTA。  
首批建议方向：专业服务与律师事务所、制造业与外贸企业、零售与消费品牌、农牧与生产管理、公益组织与基金会。全部标“建议首批/需真实经验核实”；禁止将行业假设或推测的 KPI 写成客户成果。

## 案例页

**H1：** 交付模式与经授权案例。  
**导语：** 我们按可公开的事实展示问题、方法、交付物和状态；未获客户授权的项目不会以客户案例或量化结果呈现。

状态文案：

- `live`：已上线且获公开授权。
- `in-development`：正在开发，范围和公开信息有限。
- `pilot`：受限范围试点，尚不代表规模化成果。
- `demo`：演示原型，不代表客户上线。
- `concept`：方法概念，不代表已交付项目。

待事实与状态确认的候选方向：律所中英文官网与后台、公益基金会官网、外贸家具库存查询、农牧录单与生产管理。它们只能作为候选方法示例，不能自行标记为 `live` 或赋予量化结果。

## 关于页

**H1：** 用业务问题来定义 AI 交付。  
**正文：** 原点向量关注的是团队是否能持续使用、复盘并改进一套工作流。关于团队、经历、主体与公开项目的内容，仅以可验证、获授权的材料为准。  
**待确认禁区：** 任职年限、上市企业、项目规模、客户名称、量化结果、资质与获奖信息。

## API 平台与客户工作区

**API 导语（待确认）：** API 平台的模型范围、账户开通、价格、速率、数据处理、支持与状态，以平台实时公开说明为准。  
**Portal 导语（待确认）：** 客户工作区仅对获得邀请的用户开放；不在公开网站展示客户数据、项目状态或登录成功假象。

## 联系页与 FAQ

**联系页 H1：** 从一个具体场景开始讨论。  
**说明：** 请说明团队、目标流程、现有资料、约束和希望验证的结果；我们会根据[已确认的响应机制]判断是否适合进入范围澄清。

FAQ 至少回答 12 个采购问题：适合什么团队、需要准备什么资料、周期如何评估、报价如何形成、网站与数字化门户有何不同、定制系统和 SaaS 怎么选、知识库和网盘有什么区别、是否需要训练大模型、如何处理数据/权限/保密、库存或生产系统如何接入、AI 客服需要什么资料、官网 SEO/GEO 如何衡量；另说明案例状态、API/Portal 是否可用。所有回答不得承诺未确认的价格、周期、SLA 或结果。

## 交付流程页

**H1：** 从初步沟通到验收维护，每一步都可理解、可确认。  
页面以七步呈现：初步沟通、业务诊断、需求与范围确认、原型或 Demo、开发与测试、上线与培训、验收与维护。每步固定展示“客户需要提供什么、我们做什么、会得到什么、如何验收”，不将 Demo 或预览称为上线。
